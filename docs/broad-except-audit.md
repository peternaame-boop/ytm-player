# Broad-except audit — scoped notes

This is **not** the whole-app audit the project guidance refers to; that
document is not in the tree. It records only sites added since, with the
category the guidance asks for (KEEP / NARROW / PROMOTE).

| Site | Category | Why |
|---|---|---|
| `src/ytm_player/app/_app.py`, `YTMPlayerApp.on_unmount` → `_step` | KEEP | Independent best-effort shutdown. Each cleanup step (session save, IPC stop, PID removal, timer stop, final listen, player callbacks and shutdown, active prefetch cancel, resolver cache, media integrations, Discord, history close, cache close) is attempted even when an earlier one raised; the failure is logged with the step name via `logger.exception` and a resource reference is dropped only when its step completed. Cancellation is a separate boundary: it is remembered, the remaining steps still run, and it is re-raised at the end, so a cancelled shutdown is never reported as an ordinary success. |
| `src/ytm_player/services/player.py`, `Player._finish_load` | KEEP | Moves the existing `Player.play` load-error boundary into the native worker. Logs the exception, reports one owned ERROR event, and never publishes a superseded load's state or failure. Cancellation remains a separate boundary in the async waiter. |
| `src/ytm_player/services/auth.py`, `_extract_browser_jar` → per-root extract | KEEP | Best-effort fallback across candidate Zen profile roots. One stale/empty root (e.g. leftover `~/.zen`) must not shadow the real profile, so its failure is logged at debug level and the next root is tried; callers keep their existing behaviour (`_detect_browser` skips the browser, `_extract_and_save` reports failure). If no root succeeds the last error propagates. |
| `src/ytm_player/services/auth.py`, `_extract_browser_jar` → per-keyring retry | KEEP | Best-effort Linux fallback for Chromium-based browsers whose default extraction found no signed-in YouTube session (yt-dlp guessed the wrong keyring). Each keyring backend is tried in turn; one that is missing or fails (no Secret Service, no KWallet) is logged at debug level and the next is tried. If none yields a signed-in session, the default extraction's jar is returned, so callers behave exactly as without the retry. |
| `src/ytm_player/services/mpris.py`, `MPRISService.start` → export and name request | KEEP | Startup must continue without MPRIS. A session bus that accepts the connection but refuses the interfaces or the name (a sandboxed bus, for example) is logged as a warning with its traceback, the connection is closed and the partial state cleared, and the service stays off for the run. The caller awaits `start()` unguarded in `on_mount`, so an escape here would stop the app. |
| `src/ytm_player/utils/report.py`: `_guarded`, the per-dependency lookup in `probe_dependencies`, the dependency block and the section loop in `_collect`, `probe_main`, and the module imports in `probe_libmpv` / `probe_mpris`; `src/ytm_player/utils/doctor.py`: `_safe` | KEEP | The diagnostics have to print on a broken install, and the public report must never show exception text. A collector that fails for an unforeseen reason becomes a fixed status line carrying only the exception class name, and only when that name is in the report's closed set (`other` otherwise); `doctor._safe` does the same for each `ytm doctor --local` collector. `probe_main` runs in the child interpreter that loads third-party code (the dependency lookups, python-mpv/libmpv, dbus-fast, tomli, packaging): whatever a probe raises is sent back as a class name, which the parent maps to that closed set. Importing `services/player.py` or `services/mpris.py` there can raise anything a broken third-party build raises, so those two imports are caught the same way. Nothing is logged: the diagnostics run with logging silenced so that they stay off stderr. |
